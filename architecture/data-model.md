# ICP + ZenDB data model

## Model boundary

`meritocracy_core` is the authoritative owner for every on-chain entity below.  ZenDB is used only for bounded, indexed documents and never as the sole source for identity, vote uniqueness, eligibility, policy, reserve, or payment-state decisions.  The asset canister owns only release assets.  All monetary values are non-negative integer smallest units; legacy `DECIMAL` and `DOUBLE PRECISION` values require an approved fixed-point conversion.

Identifiers are generated independently of PostgreSQL: principal/account IDs are ICP principals; period IDs are canonical UTC period strings; run, obligation, audit, and work IDs are deterministic opaque IDs derived from domain inputs plus a nonce/idempotency key.  A legacy numeric ID is migration metadata only.

Privacy labels: **public** means explicitly consented and suitable for replication; **restricted** is exposed only through caller/role-authorized interfaces but is still not secret from replication; **off-chain private** must never enter canister state.

## Global constraints

- Every update has actor authorization, finite transition validation, an idempotency key, expected version where races matter, fixed input/document caps, and an atomic redacted audit event.
- Cursor tokens encode the index tuple plus immutable tie-breaker ID; they are opaque, signed/versioned and reject changed filter/sort parameters. Maximum page sizes are policy configuration; exact values are **UNKNOWN**.
- Indexes are maintained only for declared bounded queries. A scheduled batch always takes `(cursor, limit)` and never scans all accounts, votes, obligations, or audit entries.
- Asset bytes and raw evidence/logs are not ZenDB documents. Immutable UI bytes belong in `meritocracy_assets`; private evidence/logs in protected object storage.
