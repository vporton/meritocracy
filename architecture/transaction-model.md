# Transaction model

## Rules

`meritocracy_core` is the transaction owner for authoritative accounts, votes,
period decisions, reserves, obligations, work items, indexes/projections, and audit
facts. A state-changing update performs **validate → calculate → commit** with no
`await`. The commit includes its command receipt and redacted audit event. ZenDB is
a projection, never an authority; it must be written in the same update only if its
transaction/upgrade guarantees are accepted. Otherwise its update is a rebuildable
outbox work item (**UNKNOWN**: ZenDB guarantees have not yet been established).

No cross-canister call can share an atomic transaction with core state. Therefore an
external effect is represented by a durably committed intent/claim before the await,
then a separate, idempotent result/reconciliation update. There is no rollback of a
ledger transfer, email, provider verification, or AI request.

### Await-boundary audit

The only intentional pre-await mutations are: account deletion's durable erasure work,
assessment work claims, notification work creation, payment obligation authorization/
`executing` claims, and any reconciliation work claim. Each is an intent or lease, not
an assertion that the external effect happened. Any implementation that mutates an
Account, Vote, Period outcome, Reserve allocation, settled obligation, or accepted
assessment **before** awaiting an external result without recording an explicit
recoverable state machine is prohibited.
